<objective>
新增第三个 `release` 汇合 job 统一建 GitHub Release,并把 windows `build` job 末尾既有的 `Create GitHub Release` 步骤整段移走(D-02),使 Windows 安装包与 macOS dmg 一次性挂到同一个 Release 上。

Purpose: 两个 build job 各自调 `softprops/action-gh-release` 会并发创建/覆盖同一个 Release,这是确定会踩的竞态;D-02 用「build job 只上传 artifact、由唯一 release job 统一发布」根除它。这是本 phase 对 Windows 的**唯一**风险面 —— 被改动的是已经在跑 v0.1.x 的真实发版通道,所以 D-02 被评为 costly,验收标准里必须包含一次 `workflow_dispatch` 确认 Windows artifact 依然齐备。

Output: `release` job + windows `build` job 末尾发布步骤的移除。
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 两个 build job 的 artifact → GitHub Release 上的公开下载资产 | 汇合 job 决定了最终挂上去的是哪些文件;挂错、挂漏或被并发覆盖,用户下到的就是错的包 |
| 已上线的 v0.1.x Windows 发版通道 → 本 phase 的改动 | 这是本 phase 唯一触碰的生产路径,失效要到真正推 tag 那一刻才暴露 |
| `GITHUB_TOKEN`(`contents: write`)→ Release 创建权限 | 汇合 job 是全工作流唯一使用该权限写 Release 的地方 |
