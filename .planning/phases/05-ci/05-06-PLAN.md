<objective>
在用户的 arm64 Mac 上,对 CI 真实产出的 dmg 走完「下载 → 拖到 /Applications → 双击 → 观察拦截 → 启动一个 Chrome 配置」全流程,并逐条记录首次启动的完整提示序列与 quarantine 属性的实测状态。

Purpose: 本 phase 有一整类交付物没有任何自动断言能覆盖 —— 图标观感、Cmd+Q 手感、dmg 拖拽体验,以及最要害的:**未签名应用在真实 Gatekeeper 交互下到底会发生什么**。`05-RESEARCH.md` 用脚本化实测推翻了 D-12 的核心前提(App Translocation 与目标目录无关,应用自剥离在首次启动时必然失败),但那是 AppleScript 驱动 Finder 的模拟,与真人双击 + 真实系统对话框之间是否存在系统性差异仍未验证 —— 尤其是走完官方「仍要打开」之后,quarantine 属性究竟是被清除(那么第二次启动一切正常、自剥离生效)还是只在 syspolicy 数据库记一条豁免(那么 translocation 持续、用户必须敲命令)。这两种结局对 Phase 6 的发布文档写法影响完全不同,现在发现比 Phase 6 便宜。

与 Phase 6 的分工:本 checkpoint 只验「包能不能装、能不能跑」;Phase 6 验「用户仅凭发布文档能否自助完成全流程」。

Output: 一份逐项确认结论(通过 / 需修正 + 具体问题)写入 SUMMARY,供 `/gsd-verify-work` 直接引用。
</objective>

    **A. dmg 打开体验(PKG-04)**
    1. 双击 dmg 挂载,确认自定义背景图**正确显示**(不是空白窗口、不是默认灰底)。

    4. 把应用图标拖到 Applications 别名上完成安装,确认拖拽顺畅、复制过程正常结束。
    5. 卸载 dmg。

    **B. 首次启动的完整提示序列(PKG-03 / D-12a —— 本 checkpoint 的头号目标)**
    这一组请**按顺序逐条记录你实际看到的东西**,而不是只记最后能不能启动。
    1. 在 Finder 里打开 `/Applications`,**双击** Open-Anti-Browser。把从这一刻起屏幕上出现的每一个对话框都记下来:标题是什么、正文大意、有哪些按钮。特别要分清两类:一类是 **macOS 系统弹出的** Gatekeeper 拒绝/警告对话框,另一类是 **本应用自己弹出的** quarantine 剥离失败提示。两者都有?只有其中一个?先后顺序是什么?
    2. 如果看到了本应用自己的那个提示,把它的文案与 `05-02-SUMMARY.md` 里记录的 `build_quarantine_failure_message(None)` 逐字输出做比对,确认一致;并确认里面给出的命令是可以整段选中复制的、指向的是 `/Applications/Open-Anti-Browser.app` 而不是某个 `/private/var/folders/...` 的随机路径。
    3. 在终端里执行 `xattr -p com.apple.quarantine /Applications/Open-Anti-Browser.app` 并记录输出(有值 / 报 No such xattr)。
    4. 如果应用起来了,在终端执行 `ps -Ao pid,command | grep -i open-anti-browser | grep -v grep`,记录进程的完整路径,**确认它是否包含 `/AppTranslocation/`**。
    5. 现在走**官方放行路径**:系统设置 → 隐私与安全性 → 安全性区域,找到关于被阻止应用的那条提示,点「仍要打开」,按提示输入密码/指纹。记录这条路径上每一步的实际菜单名与按钮文字(注意:这与 Phase 4 已在真机核对过的应用内指引是同一套流程,若发现措辞对不上要明确指出)。
    6. 放行后再次执行 `xattr -p com.apple.quarantine /Applications/Open-Anti-Browser.app`,记录输出。**这一条是 RESEARCH Open Question 1 的核心证据**:属性被清掉了,还是仍然在?
    7. **第二次启动**应用(先完全退出再重新双击)。记录:还弹提示吗?再跑一次第 4 步的 `ps` 命令,**进程路径里还有 `/AppTranslocation/` 吗?**
    8. 如果到这一步应用仍然无法正常使用,按提示里给的命令在终端敲一次,记录敲完之后第三次启动的表现。

    **C. Cmd+Q 与关窗行为(PKG-02 / ROADMAP SC2 / D-07)**
    1. 应用正常运行时,按 **Cmd+Q**。确认:窗口消失、**菜单栏图标也消失**、Dock 里的应用退出。
    2. 在终端执行 `ps -Ao command | grep -i open-anti-browser | grep -v grep`,确认**没有残留进程**。
    3. 重新启动应用,这次点窗口左上角的**红叉**关窗。确认:窗口消失但**菜单栏图标还在**,应用仍在后台运行(用 `ps` 确认进程还在)。点菜单栏图标能重新打开主界面。
    4. 从菜单栏图标的右键菜单点「退出程序」,确认能正常退出。
    这三种退出方式的行为差异是 D-07 刻意设计的:Cmd+Q 与菜单栏「退出程序」都真退出,红叉只最小化。

    **D. 图标与应用名观感(PKG-02)**
