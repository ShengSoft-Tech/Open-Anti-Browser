  <how-to-verify>
    在 macOS 上启动应用(`python launch_app.py`,或 `cd frontend && npm run dev` 配合后端 `python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000`),逐项确认:

    **A. 既有 Firefox 配置的能力矩阵(UI-01)**
    先在 `data/profiles.json` 里准备一个 `engine` 为 `firefox` 的配置(可从 Windows 侧导出后导入,或直接手工加一条)。然后在配置列表页确认:
    1. 该配置**出现**在列表里,带自己的 Firefox 图标与引擎标记。
    2. 它旁边多出一个「仅 Windows」标记。
    3. 启动按钮为禁用态,悬停时出现说明气泡。
    4. 「更多」下拉里的**复制**为禁用态,**删除**可用(点开确认框后可取消,不必真删)。
    5. 编辑按钮可点开;对话框里引擎选择器高亮显示 Firefox、整体禁用、下方有说明文字;改个备注保存后,该配置的 engine **仍然是 firefox**(在列表里确认引擎标记没变成 Chrome)。
    6. 勾选它 + 一个 Chrome 配置,点「启动选中项」:只有 Chrome 那个被启动,**没有**弹出任何后端报错提示。
    7. 引擎筛选下拉里**只有 Chrome**一项。
    另请确认一个规划裁量是否符合你的预期:分组管理页里每个分组仍然显示 Firefox 配置的计数(未隐藏)。理由见 04-05-SUMMARY;若你希望改成隐藏,现在提出。

    **B. Gatekeeper 放行指引(UI-04)—— 重点核销项**
    1. 在应用里打开浏览器开发者工具(或用「设置 → 平台限制说明 → 重新查看放行指引」),先清掉 localStorage 的 `oab:macos-gatekeeper-notice:v1`,刷新页面。
    2. 确认**先**弹开源声明首次使用提示,关闭后**再**弹放行指引,两者不重叠。
    3. **逐字核对指引里描述的放行路径,在你这台 Mac 的当前系统版本上是否真的存在**:先打开一次被拦截 → 系统设置 → 隐私与安全性 → 安全性区域 → 「仍要打开」→ 输入密码。菜单名称、按钮文字要和系统里实际显示的一致。这是 RESEARCH 假设 A2 的核销点 —— 如果你的系统里路径或按钮文字不是这样,现在就要改文案。
    4. 确认终端命令显示为 `xattr -dr com.apple.quarantine /Applications/Open-Anti-Browser.app`,可以整段选中复制,连字符与斜杠没有被美化或转义。
    5. 确认整篇指引**没有**让你去全局关闭 Gatekeeper、也**没有**让你对整个 Downloads 或 Applications 目录做递归操作。
    6. 点确认关闭,刷新页面,确认**不再**弹出。

    **C. 平台限制说明卡片与置灰提示的双语可读性(UI-02 / UI-03)**
    1. 打开设置页,确认「平台限制说明」卡片存在,三条说明分别点名 Firefox 内核、窗口排列/同步、首次运行放行。
    2. 用右上角语言下拉在 zh-CN 与 en-US 之间来回切换,确认卡片、同步器横幅的包装文案、列表的「仅 Windows」标记、放行指引全部随之切换,**没有任何一处仍显示另一种语言**(唯一例外:同步器横幅与导航气泡里那句「窗口同步仅在 Windows 上可用」是后端提供的中文原文,按 D-02 的既定决策在英文界面下也保持中文,这是预期行为,不是 bug)。
    3. 通读全部新文案,确认它们点名的是**具体不可用的功能**,不会让人读成「这个应用在 macOS 上不能用」。
    4. 点侧栏「同步器」:导航项是置灰的、悬停有气泡,但**点击仍能进入**视图;视图里顶部有横幅,启动同步/一键排列/显示窗口等按钮全灰,而分组筛选下拉和同步设置弹层仍可正常操作。
  </how-to-verify>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 应用内操作指引 → 用户在自己机器上执行的系统操作 | 指引一旦描述错误或过宽,用户会照做,后果发生在用户的机器上而不是本项目里 |
| 已有用户数据(Windows 迁移来的配置) → 门控后的界面 | 界面是用户判断「我的数据还在不在」的唯一依据 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06 | Elevation of Privilege(用户被诱导降低本机防护) | Gatekeeper 放行指引文案 | high | mitigate | B 组第 5 步由人工确认指引未引导全局关闭系统防护、未对宽泛目录做递归操作;这是自动断言之外的最后一道人工闸门。 |
| T-04-13 | Repudiation(误导用户) | 放行流程描述过时 | high | mitigate | B 组第 3 步要求在真机上逐字比对系统菜单与按钮文字,并记录系统版本 —— 核销 RESEARCH 假设 A2。 |
| T-04-08 | Denial of Service(用户对自己数据的可及性) | 既有 Firefox 配置的可见性与可删除性 | high | mitigate | A 组 1/4/5 项人工确认配置可见、可删、保存后 engine 未被改写。 |
