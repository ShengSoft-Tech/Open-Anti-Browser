<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 应用 → 内核二进制文件(xattr/exec) | 后端在自己触碰内核的时点(启动前)对**后端解析出的**内核路径做 xattr 操作;路径来源为 config.bundled_engine_executable,非用户输入 |
| 应用 → OS Gatekeeper/syspolicyd | CLI Popen 直接 exec 嵌套二进制,是否经 LaunchServices/Gatekeeper 由 OS 决定,超出应用控制(真机实证) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-03 | Elevation of Privilege | `xattr -dr com.apple.quarantine` 剥离目标路径 | high | mitigate | xattr 目标严格限定为 bundled_engine_executable("chrome") 解析出的内核路径(后端完全可控,无通配符、无用户可控输入拼接);best-effort try/except 包裹;单测断言路径参数精确等于解析路径(ASVS L1 V5,block-on-high 已缓解) |
| T-3-04 | Tampering | 用户手动替换内核二进制 | low | accept | 本地单用户工具信任边界 = 用户对自己机器有完全控制权,应用层无法完全防御;D-07 启动路径防御钩子间接提供"重新剥离 quarantine"的兜底点,不作为安全边界仅作可用性兜底 |
| T-3-SC | Tampering | pip 依赖供应链 | low | accept | 本 plan 不安装新包;xattr 用 macOS 系统自带命令(非 Python 第三方 xattr 包),零新依赖、无 legitimacy gate 触发 |
</threat_model>
