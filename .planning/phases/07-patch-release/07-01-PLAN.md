## 本计划落盘的 Claude's Discretion 决策

CONTEXT.md § Claude's Discretion 把若干 phase 级决策交给 planner 定夺。与本计划相关的两条在此显式落盘，执行时按此执行，不要重新权衡：

- **D-09（本计划）「本次更新」章节的双语排布与版本号书写形式：** 版本号用 HTML 注释锚点 `<!-- RELEASE_VERSION: 0.2.1 -->`，放在整个文件第 1 行，全文件**只出现一次**，中英文不各放一份。中文「## 本次更新」跟随中文区块之首（锚点之后、现有「## 下载前必读：系统要求」之前），英文「## What's Changed」跟随英文区块之首（现有「## Before You Download: System Requirements」之前），与模板既有的「中英各自完整并列」结构一致。
  理由：注释锚点在 GitHub 正文里不渲染，把「给读者看的措辞」与「给脚本读的版本号」彻底解耦——措辞/排布后续怎么调都不会碰坏门禁正则；如果改用抓标题文案的正则，中英两处标题都要抓、都要一致，排布一改正则就碎。
  — Reversibility：reversible（改锚点形式只需同步改一条正则与一个夹具）。

- **D-10（本计划）commit 切分与 bump 时机：** 分三个 commit，每个 commit 落地后 main 上的四方版本号都自洽（`check_version_consistency.py` 在非 tag 模式下要求 package.json / main.py / 模板三方相等，且 `ci-tests.yml` 会在 push 时跑全套测试——任何一个中间 commit 上三方不等都会把 main 弄红）。因此 Task 1 先以 `0.2.0` 引入锚点（与当时 main 上的版本号一致），Task 3 再把四处一起 bump 到 `0.2.1`。tag 不在本计划创建。

D-01（模板新增「本次更新」章节）在 CONTEXT.md 里被标记为 **costly**：模板从此由「版本无关、零维护」变成「每次发版必改」，且这个属性会被 D-02 的门禁固化成发版流程的硬约束。这不阻塞执行，但请在 SUMMARY 里如实记录这一属性变化。
</phase_decisions>
