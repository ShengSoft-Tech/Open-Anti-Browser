## 本计划落盘的 Claude's Discretion 决策

CONTEXT.md § Claude's Discretion 把以下 phase 级决策交给 planner 定夺。执行时按此执行，不要临场重新权衡：

- **D-11（phase 级）发版与验证的先后排序 = 先发后验，三条 SC 全部锚定在同一份真实 Release 产物上。** SC1 的关闭按钮真机实测使用 **v0.2.1 Release 页面上的 dmg**，不使用 tag push 之前 `workflow_dispatch` 产出的临时 artifact。
  理由：(a) ROADMAP 已约束三条 SC 共享同一次 tag push；(b) `release` job 在 workflow_dispatch 下恒 skip，SC2/SC3 本来就只能后验，若 SC1 前验则三条 SC 会落在两份不同产物上，证据链分叉；(c) 07-RESEARCH Pitfall 4 要求 SC1 的载体必须是冻结的 `.app`，而「最终发布产物」比「临时 artifact」更贴合 SC1「真机实证」的语义。
  已知代价：若 SC1 在发布后被判失败，修复需要对用户可见地再发一个版本号。该代价由 Task 1 的 checkpoint 显式呈交人工确认。
  — Reversibility：**one-way** —— 已发布的 Release 对公众可见，`v0.2.1` 这个版本号无法重用。

- **D-12（phase 级）SC1 的验证载体 = 冻结的 `.app`（来自 v0.2.1 Release 的 dmg），覆盖三条退出路径。** 源码直跑 `python launch_app.py` **不被接受**为等价证据（07-RESEARCH Pitfall 4：05-02 SIGSEGV 与 05-06 Quit 死循环两次真机缺陷都只在 PyInstaller 冻结包里复现过）。详见 07-03。

- **D-13（phase 级，RESOLVED — 结论为不可行，非待办）给 `build-macos` 的 GUI 冒烟门禁加第三维度（AppleScript 点关闭按钮并断言进程退出）：不做，本条讨论就此关闭。** 「点击某个具体窗口的关闭按钮」在 AppleScript 里必须走 `System Events` 的 UI Scripting，该能力被 macOS 的 `kTCCServiceAccessibility` 网关；GitHub-hosted macOS runner 保持 SIP 开启、无非交互授权渠道，连直接改写 TCC.db 的常见变通也走不通（07-RESEARCH Pitfall 3 / 假设 A3）。这不是「暂时没做」，是托管 runner 的架构性限制。现有两维度门禁（18s 存活防 SIGSEGV 回归 + `osascript ... to quit` 有界退出防死循环回归）已是 CI 侧上限。**任何计划或执行动作都不得再尝试添加该维度。**

- **D-14（phase 级）A2 被推翻时的处置 = 只记录判定，不就地调模板排版。** 若观测到自动 changelog 排在手写正文之前，本 phase 只把判定写进记录并回填假设行（07-03 Task 3），**不**改模板排版——排版改动需要另一次真实 tag push 才能验证，与「一次发版」的约束直接冲突。排版调整若确有必要，另开 phase。

- **D-15（phase 级）失败回退策略 = 取证优先的三段式，不删 tag、不烧新版本号。** 若 SC2 未达成（正文没有渲染出模板内容）：
  1. **第一步（强制，不可跳过）**：在任何补救动作之前先取证——`gh release view v0.2.1` 的正文原文与元数据落盘，SC2 判为 FAIL 并把失败正文原文完整保留。取证是本 phase 的核心产出，补救会摧毁它。
  2. **第二步**：不执行 07-RESEARCH Pitfall 5 的路径 (b)（删远程 tag + 删 Release + 重推同名 tag）——它依赖未实测的假设 A2，且已发布 tag 被重写会影响已拉取用户；也不执行路径 (c)（烧 `v0.2.2`）——为一个纯文案缺陷重发全部安装包代价不成比例，v0.2.1 的 dmg/exe 资产与正文渲染无关、本身仍然可用。
  3. **第三步**：取证落盘后，经人工确认（07-03 的复核 checkpoint）再用 `gh release edit` 手工补正面向用户的正文——并在同一份记录里显式标注「本次由人工补救，PKG-06 未达成」，把根因路由到后续 phase。
